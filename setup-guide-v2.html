Setup Guide v2 — Personal Accounts
This path skips GitHub organisations and Copilot Business entirely — no seat management, no pause blocking you, no waiting. Everything runs on personal GitHub accounts with either the free Copilot tier or a $10/month Pro upgrade.
✓ You are here — Personal accounts (v2)
Org + Copilot Business (v1) — see facilitator-setup-guide.html
0
Which accounts do I actually need?
Read this before clicking anything
i
This guide is for YOUR accounts, not the whole class

You need: your own account (to build the repo, test everything, and help students on the day), and optionally one test account if you want a second pair of hands for Friday's run-through.

On the real session day, every student creates their own GitHub account, following participant-guide.html — exactly as already planned. You are not creating accounts for them. Copilot activates automatically on their own account with zero action from you (more on that in Step 3).

1
Get an email address, if you need one
Only needed for a second test account — skip if you're only setting up yourself
1
GitHub needs one email per account

If you're just setting up your own account, you almost certainly already have an email — skip to Step 2.

If you want a second test account, you need a second, different email address for it. The quickest way: go to gmail.com → Create account → follow the prompts. Takes about 3 minutes, no cost.

Tip
Something like yourname.novapaytest@gmail.com makes it obvious later which account is which.
2
Create your GitHub account(s)
1
Sign up at github.com

Go to github.com → Sign up → enter the email, choose a password, choose a username → verify the email when the code arrives.

Repeat with the second email if you're setting up a test account too.

3
Turn on Copilot — per account
No org, no admin approval, no seat assignment — this is entirely self-serve
i
Good news first: Free just works, automatically

The moment a personal GitHub account exists, Copilot's Free tier is already active on it — 2,000 code completions and 50 chat messages a month, no card, no toggle to switch on. If you're just testing today, you can genuinely skip straight to Step 4 and come back to this only if you decide you want more headroom.

2
Upgrade to Pro (recommended for your own account)

While logged into the account you want to upgrade: click your profile photo (top right) → Settings → Copilot in the left menu → Change plan → choose Copilot Pro → confirm payment ($10/month).

What this buys you
Unlimited code completions (Free is capped at 2,000/month) and a much larger chat allowance (roughly $15 of credit versus Free's 50-message cap) — comfortable headroom for a full day of heavy use.
3
Decide for your test account

Start it on Free. If the 50-message chat cap gets hit during Friday's run-through, that's your real-world signal to upgrade — repeat the same steps above on that account.

4
Build the workshop repo
On your personal account — no organisation involved
1
Create a new public repository

While logged in as you (not the test account): click + top right → New repository → name it novapay-workshop → set Public → tick Add a README file → Create repository.

2
Upload the two workshop files

Add file → Upload files → drag in bank-dashboard.html, starter-template.html, and challenge.js → Commit changes.

3
Add the Codespaces config

Add file → Create new file → filename exactly:

.devcontainer/devcontainer.json

Paste in the contents of your devcontainer.json file → Commit new file.

4
Make it a template repository

Repo Settings → tick Template repository. This is what lets each student click "Use this template" to get their own copy.

One step you get to skip
On the org/Business path, there's a "set Copilot access to all repositories" policy step here. On personal accounts, there's no such policy to set — Copilot just works in every repo the account touches, automatically. One less thing that can go wrong.
5
Install Nova
Identical to the org path — this file doesn't care whether an org exists
1
Create the instructions file

On the same repo: Add file → Create new file → filename exactly:

.github/copilot-instructions.md

Paste in the full contents of copilot-instructions.md from your materials pack → Commit changes.

Confirmed compatible
Repository-level custom instructions like this are supported on GitHub's Free, Pro, and Team plans — this isn't a Business/Enterprise-only feature. Nova works exactly the same regardless of which individual plan is behind each account.
6
Test end-to-end
Do this on Friday — ideally with both accounts if you set up two
1
Copy the template

Logged in as whichever account you're testing: go to your repo → Use this template → Create a new repository → name it something like test-novapay.

2
Open a Codespace and the preview

Code → Codespaces → Create codespace on main → wait for it to load → right-click bank-dashboard.html → Open with Live Server → confirm the dashboard renders.

3
Confirm Nova is active

Open Copilot Chat → type: Who are you? → it should describe itself as a NovaPay mentor, not generic Copilot.

If it doesn't
Double-check the exact filename from Step 5 — that's the only thing that commonly goes wrong, on either setup path.
4
If testing on the Free tier, keep an eye on the chat count

Have a handful of back-and-forth conversations with Nova across the bug hunt and build phases, roughly matching a real day's usage. If you're nowhere near 50 messages, Free is fine for that account. If you're closing in on it fast, upgrade that account to Pro before the real session.

5
Clean up

Test repo's Settings → scroll to the bottom → Delete this repository.
