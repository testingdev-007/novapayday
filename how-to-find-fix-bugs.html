How to Find & Fix a Bug
A real, click-by-click walkthrough. We'll use a made-up example first so nothing here spoils the real bugs in the dashboard — then you'll use the exact same method on the actual file.
I'm in:
The Method
Four steps, every single time
This is the entire loop. Professional developers do exactly this, all day, every day.
👀
1. Look
Open the preview. Does anything look visually wrong — missing, invisible, misaligned, the wrong colour?
🖱️
2. Use
Click every button. Type in every field. Does something not respond, or do the opposite of what it should?
📖
3. Read
Open the code. Read it slowly, line by line. Typos and small mistakes hide in plain sight.
✅
4. Test
Make your fix, save, and check the preview again. Did it actually work? Don't assume — look.
Worked Example
Let's fix a bug together first
This example is not from the real dashboard — it's just here so you can see the exact clicks before you try it for real.
1
Imagine you see this on a page

There's a button that's supposed to show a greeting. You click it. Nothing happens. No error, no message — just silence.

2
Look → nothing to see here

The button looks completely normal. This isn't a visual bug — Look tells you nothing's obviously wrong, so move to the next step.

3
Use → confirmed, it's broken

You click the button. Nothing happens. That confirms there IS a bug — now you know where to look in the code.

4
Read → open the code and look closely

Click on the file in your file panel to open it. You find this:

<!-- The button -->
<button onclick="sayHi()">Click me</button>

// The function -->
function sayHu() {
  alert("Hi!");
}

Read it slowly. The button calls a function called sayHi(). But the function is actually named sayHu() — one letter different. JavaScript can't find a function that doesn't exist, so it just quietly does nothing.

This is the single most common type of bug
A name doesn't match somewhere else. Your eye skips over it because both spellings look like they should be the same word.
5
Fix it — the exact clicks

Click right before the u in sayHu. Press Backspace to delete it. Type i instead. You now have:

function sayHi() {
  alert("Hi!");
}

Press Ctrl+S (Windows) or Cmd+S (Mac) to save.

6
Test it — did it actually work?

Click over to your Live Server preview tab. Because Live Server watches for saves, the page has already refreshed automatically. Click the button again.

You should see
A popup box appears saying "Hi!" — the bug is fixed, and you've confirmed it by actually testing it, not just assuming.
Now For Real
Apply this to the actual dashboard
Same four steps. We won't tell you what the bugs are — that's the whole exercise — but here's exactly how to run the process.
1
Look — go through the page top to bottom

Open your Live Server preview tab for bank-dashboard.html. Scroll from the very top to the very bottom slowly. For each section, ask: does this look right? Is anything missing, invisible, or in the wrong place?

2
Use — click and type on absolutely everything

Click every button on the page. Type a normal number into every input field and see what happens. Then get a bit naughty — try these on purpose:

Leave a field empty
Click the button without typing anything first
Type letters, not numbers
Into a field that expects an amount
Type a negative number
Like -50, where it wouldn't make sense
Type a huge number
Bigger than the amounts on the page

Every time something looks wrong or doesn't behave the way you'd expect a real banking app to behave — that's a bug. Write it in your Bug Test Plan straight away, before you forget.

Y11+ Stretch
Before you fix anything, write down your best guess for why it's broken, in your own words. Check your guess once you've read the code.
Y12–13 Stretch
Try to categorise each bug as you find it: is it a typo, a logic error (the maths or condition is wrong), or a missing check (nothing stops bad input)? Naming the category before you fix it is exactly what a real code review looks like.
3
Read — open the code and slow down

Click on bank-dashboard.html in your file panel. Read the HTML first, top to bottom. Then read the CSS. Then read the JavaScript at the bottom, one line at a time.

For every line, ask yourself: does this say what I think it says? Compare names carefully — an id used in one place has to be spelled exactly the same everywhere else it's used.

Open the console too
Press F12, click the Console tab, then try using the page again. Red text in there is JavaScript telling you exactly where it got confused — genuinely one of the most useful clues you have.
Y12–13 Stretch
For one bug, write a proper one-sentence bug report the way a real team would file it: "Expected X to happen when doing Y. Instead, Z happened." This is the actual skill of turning a vague "it's broken" into something someone else could act on.
4
Fix it — the same mechanics as the example

Click into the exact spot in the code that's wrong. Delete what's incorrect, type the correction. Save with Ctrl+S / Cmd+S.

5
Test it — prove it, don't assume it

Switch to the Live Server tab. Do the exact same thing that was broken before — click the same button, type the same value. Does it now behave correctly?

If yes — log it in your Bug Test Plan (what was wrong, how you found it, what you changed) and go back to Step 1 for the next bug. If no — you haven't found the real bug yet, or your fix didn't quite work. Go back to Step 3 and read more carefully.

Good To Know
The kinds of bugs you'll likely meet
General categories, not specific answers — knowing the shape of a problem helps you spot it faster.
🔤 Typos in names
A function, an id, or an attribute spelled slightly differently in two places. Read character by character, not just the shape of the word.
🎨 Colours that hide things
Text the same colour as its background is invisible but still there. Try clicking and dragging where you think text should be.
🧮 Maths that's backwards
A calculation that does the opposite of what it should, or is scaled wrong. Test with numbers you can check in your head.
🚫 Missing checks
Nothing stops you entering something silly (empty, negative, huge). That's what your "Use" step on purpose is for.
Getting Unstuck
Exactly what to type to Nova
If you've done Look, Use, and Read, and you're still stuck — these prompts work well.
"I clicked this button and nothing happened. Here's the code around it — what's wrong?"
"The console shows this error: [paste the red text]. What does it mean?"
"I expected X to happen when I did Y, but Z happened instead. Why?"
Nova will hint, not just answer
That's on purpose — it'll point you toward the right area rather than just telling you the fix outright. Keep asking follow-up questions if the first hint doesn't quite land.
🎯 That's the whole method
Look, Use, Read, Fix, Test. Repeat it for every bug you find. It's the same loop real developers run all day — you're just running it on a smaller scale.
