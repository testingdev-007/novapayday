Before You Start
Get your screen set up
0
Create a genuinely empty file

In your file panel, right-click anywhere empty → New File → name it practice-feature.html. This is completely blank — no styling, no header, nothing. That's deliberate.

Right-click it → Open with Live Server so you have a preview tab too.

Right-click → New File → Right-click → Open with Live Server

Keep both tabs open the whole time — you'll flip between them constantly.

Why start from nothing?
Later, when you build your own idea, you'll copy styling from a file you've already built rather than starting cold. This tutorial is where you actually learn what that styling is and how it gets made — not just where to copy it from.
Building the Foundation
Step 1 of 10 — The basic page skeleton
1
Type a comment at the very top of the empty file
Type this comment
<!-- a basic HTML5 page with a title "NovaPay — Savings Goal Tracker" -->

Press Tab. Copilot should suggest the standard HTML skeleton — <!DOCTYPE html>, <head>, <body>, and so on. Accept it and save with Ctrl+S.

What you should see
Switch to Live Server — a blank white page with the correct browser tab title. Nothing visible in the page body yet. That's correct.
Step 2 of 10 — A colour system you'll reuse everywhere
2
Inside the <head>, add a <style> section
Type this comment
/* a NovaPay colour palette using CSS variables: purple accent, green success colour, light grey background, dark text, plus a card style with rounded corners and a soft shadow */

Press Tab. Save.

What you should see
Still nothing visible — you've defined a colour system (things like --accent, --green) but nothing on the page uses it yet. That's the next step.
This is the reusable bit
These CSS variables are exactly what you'll copy into your own feature later — one colour system, used consistently everywhere, instead of picking random colours per page.
Step 3 of 10 — The NovaPay header bar
3
Inside <body>, add the header
Type this comment
<!-- a sticky header bar with the NovaPay logo on the left, using the accent colour -->

Press Tab. Save.

What you should see
Switch to Live Server — a header bar now appears at the top of an otherwise blank page, styled with your colour system from Step 2.
If it looks unstyled or plain
Check the header HTML actually uses a class your CSS defines — read both pieces and make sure the names match exactly. Ask Nova: "My header isn't picking up my styles — here's my CSS and HTML, what's wrong?"
Step 4 of 10 — The input card
4
Below the header, add the form
Type this comment
<!-- a card with three inputs: goal name (text), target amount (number), amount saved so far (number), and a button labelled "Update my goal" -->

Press Tab. Save.

What you should see
A styled card with three input boxes and a button, using your colours from Step 2. You can click into the boxes and type — nothing happens on button click yet, and that's fine.
✓ Foundation check: you now have a styled page with a header and an input form — built entirely from a blank file. Everything from here reuses what you just made.
Step 5 of 10
Style the progress bar
5
Back in your <style> section
Type this comment
/* progress bar container and fill styles, using the colour variables from before */

Wait a second — grey ghost text should appear underneath, suggesting CSS code. Press Tab to accept it.

What you should see
A block of new CSS code appears, styling something called .progress-track and .progress-fill. Save with Ctrl+S.
Nothing visible changes yet — that's normal
You've only written the styling rules. Nothing on the page uses them yet because you haven't added the HTML that needs them. That's the next step.
Step 6 of 10 — Style the result message
6
Right below that
Type this comment
/* styles for a result card showing a large amount remaining and a status message */

Press Tab to accept the suggestion. Save with Ctrl+S.

What you should see
More CSS appears, this time styling a result box. Still nothing visible in the preview — same reason as before.
Now Things Get Visible Again
Step 7 of 10 — Add the progress bar HTML
7
Below your input card in the HTML
Type this comment
<!-- savings goal progress card with a labelled progress bar and percentage -->

Press Tab. Save with Ctrl+S.

What you should see
Switch to your Live Server tab and refresh (it should update automatically, but refresh manually if not). A new card should now be visible on the page — a progress bar, even if it's showing 0% right now.
If you DON'T see it
Check the editor tab for a red squiggly line anywhere — that means a typo broke the HTML. Also confirm you saved (the tab title has a dot on it if unsaved). If it still doesn't show, ask Nova: "I added a progress card but it's not showing on the page — here's my code, what's wrong?"
Step 8 of 10 — Add the result HTML
8
Right below that
Type this comment
<!-- result card showing amount left to save and a congratulations message if goal met -->

Press Tab. Save.

What you should see
A second new card appears below the progress bar in your preview — this is where the "amount left" message will eventually show.
✓ Milestone check: your page now has a header, inputs, a button, a progress bar, and a result area — all built by you, from nothing. None of it works yet. That's exactly on track.
The Logic
Step 9 of 10 — The calculation and display
9a
Add a <script> section at the bottom of the page

Just before </body>, add a <script> tag — an empty one is fine, Copilot will fill it as you go.

9b
Inside it, the calculation function
Type this comment
// function calculateProgress(savedAmount, // targetAmount) that returns the percentage // saved, capped at 100, rounded to 1 decimal

Press Tab. Save.

What you should see
A new function appears in the code. Nothing changes in the preview — this function exists but nothing calls it yet.
9c
Right below it, the display update function
Type this comment
// function updateDisplay(goalName, targetAmount, // savedAmount, percentage) that updates the // progress bar width, percentage text, // amount remaining, and shows a // congratulations message if goal is met

Press Tab — this one's bigger, Copilot might suggest it in a few chunks. Keep pressing Tab to accept each part. Save.

What you should see
Still no visible change — this function is ready to run but hasn't been triggered by anything yet. One step to go.
The Big Moment
Step 10 of 10 — Wire it all together
10
Add the button's click function

This is the function that runs when someone clicks the button. Add an empty one:

function updateGoal() {
  // YOUR CODE GOES HERE
}

Click on that comment line and replace it with this comment, then press Tab:

Type this comment
// read goalName, targetAmount and savedAmount // from the inputs, validate them, calculate // progress, and update the display

Copilot should generate several lines that read your three input boxes and call the two functions you already built. Save with Ctrl+S.

✓
Test the whole thing for real

Switch to your Live Server preview tab. Fill in the three boxes with real numbers:

Goal name: "New trainers" Target: 80 Saved so far: 50

Click Update my goal.

What you should see
The progress bar should animate and fill to roughly 62%. The result card should show something like "£30.00 left to save."
If nothing happens when you click the button
Press F12, click Console, click the button again — look for red text. Copy it and ask Nova: "I clicked my button and got this error: [paste it]. What's wrong?"
🎉 If the bar filled in and the message appeared — your feature works. That's genuinely the hardest part done.
Now Break It On Purpose
Check it properly before you demo it
Try each of these. For each one, decide: is this OK, or does it need fixing?

Leave all three boxes empty and click the button. Does it show something sensible, or does it break?

Type a savings amount bigger than the target. Does the bar go past 100%, or does it cap sensibly?

Type a negative number. Does anything stop you, or does it just show something nonsensical?

Log whatever you find in your Feature Test Plan. If something breaks that shouldn't, that's your next thing to fix — ask Nova: "How do I stop someone entering a negative number here?"

Y12–13 Stretch
Once this is solid, try adding localStorage so the goal survives a page refresh — describe it as a comment the same way you built everything else: "save goalName, targetAmount, and savedAmount to localStorage, and load them back in when the page opens."
Iterating
How to change something once it's built

Want to change how it looks? Find the relevant CSS rule (search for the class name, e.g. .progress-fill), change the value (a colour, a size), save, and check the preview.

Want to change how it behaves? Find the relevant function in the JavaScript, describe your change as a new comment right above the line you want different, and let Copilot suggest an update — or ask Nova directly: "How do I make X happen instead of Y?"

Got a wall of red errors? Don't panic — read only the first one, it's usually the real problem. Fix that, save, and see if the others disappear on their own.

Your Turn
Starting your own feature
You've just built one feature end to end. Here's how to start a brand new page for your own idea — and how to make it look like it belongs on NovaPay without starting from scratch on the styling.
1
Create a new file

In your file panel, right-click anywhere empty → New File → give it a sensible name for your idea, e.g. currency-converter.html or my-feature.html. Anything's fine — this is your file, name it however makes sense to you.

2
Carry the NovaPay look across

Rather than styling everything from zero again, open practice-feature.html — the file you just built — in another tab, and copy across the bits that give it the NovaPay feel: the <style> section with your colour variables, and the header bar with the logo. Paste them into your new file.

This is a completely normal thing developers do all the time — reusing your own earlier work as a starting point rather than reinventing it. You're not cheating by doing this; you're being efficient.

3
Build it with the exact same method

Comment → Tab → save → check the preview → ask Nova if something's wrong → repeat. You've done this whole loop once already today. Nothing changes except the idea.

🚀 The method never changes
Comment → Tab → Save → Test → Ask Nova if stuck → Repeat. Whatever you're building next — this feature's stretch goals, or a completely different idea — this is the whole loop.
