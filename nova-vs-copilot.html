🔍 Objective comparison, not marketing
Nova vs Plain Copilot
Same underlying tool. One extra text file. Here's exactly what changes, why it changes, real evidence of the difference, and where the honest limits are.
← Back to facilitator training
The mechanism — what's actually different
Plain Copilot
Copilot Chat with no custom instructions answers from its general training — helpful, broadly competent, but with no idea it's talking to a 13-year-old during a structured bug hunt, and no reason to hold back a complete answer if asked for one.
Nova
The exact same Copilot Chat, in the exact same repo — but with one extra file present: .github/copilot-instructions.md. Copilot reads this automatically on every chat message in this repo and adjusts its behaviour accordingly. It's not a different product, a plugin, or a separate subscription. It's context, applied automatically.
Real evidence — the same question, both ways
These are the actual behavioural rules written into Nova's instructions file, shown against what plain Copilot does with no such instructions.
Student asks, during the Bug Hunt
"Are there any bugs in this code?"
✕ Plain Copilot
Lists several or all of the bugs directly, because it has no reason not to — it's just being maximally helpful to a direct question.
Outcome: the exercise is largely defeated in one message.
✓ Nova
"Yes, several! Try this: look at the page first — does anything look visually wrong? Then try using it — click things, type things. What breaks?"
Outcome: student is redirected to the actual learning activity.
Student asks, during the Build phase
"Can you build my whole feature?"
Plain Copilot
Will attempt it if the description is clear enough — no particular reason to hold back, similar to the bug hunt case.
Not necessarily wrong here — just not tailored to the moment.
✓ Nova
Explicitly instructed to be generative here, not restrictive — Nova is told this is vibe-coding and should write complete functions freely. The difference from the Bug Hunt case is deliberate phase-awareness, not blanket caution.
Outcome: same as plain Copilot when description is clear, but Nova asks a clarifying question first if it isn't — keeping momentum either way.
Student asks, at any point
"Explain what a function is"
Plain Copilot
Gives a competent, technically accurate explanation — but written the same way for a 13-year-old as for a professional developer.
May use unexplained jargon.
✓ Nova
Instructed to keep answers short, use an everyday analogy, and translate any technical term in one line — "a function — a reusable block of code."
Outcome: same information, calibrated to the actual audience in the room.
Student asks, off-topic
"Can you help me with something unrelated to the workshop?"
Plain Copilot
Will typically just try to help with whatever's asked — it has no concept of "the workshop" or a task to stay inside.
No structural reason to redirect.
✓ Nova
"Let's get back to your feature — what part are you working on right now?" — explicitly instructed to redirect kindly rather than engage.
Outcome: keeps a room of young people on-task without you personally policing every chat window.

The honest limits — where Nova isn't magic
It's an instruction, not a lock
Nova works because the underlying model generally follows the instructions it's given — but a persistent or cleverly-worded student could still get more out of it than intended. This is guidance, not a technical restriction. Treat it as a strong nudge in the right direction, not a guarantee.
No memory between conversations
Nova doesn't "learn" a specific student over the day — every new chat starts fresh from the same instructions file. Any improvement over time comes from you editing the file between sessions, not from Nova adapting live.
Only as good as Copilot itself underneath
Nova shapes tone and boundaries — it doesn't make the underlying code suggestions more technically correct. Copilot can still be confidently wrong; Nova doesn't fix that, and nor should it try to.
🎯 The honest verdict
Nova is a genuinely better fit for a room of 13–18 year olds than plain Copilot — not because it's more powerful, but because it's more appropriate: it protects the learning objective during the Bug Hunt, gets out of the way during the Build phase, and talks to students like students. That's a real, evidenced difference. It is not a safety net that makes misuse impossible, and it doesn't need to be — for a supervised one-day workshop, "meaningfully better by default" is exactly the right bar, and Nova clears it.
