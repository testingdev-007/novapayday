Handling "Fix All Bugs"
What to do when someone asks Copilot to solve the whole thing at once.
🛡️
Your first line of defence: Copilot won't get them all
This is structural, not accidental

The bug set is designed so that a blanket "fix all bugs" prompt will always miss at least three. Bugs 8, 9, and 10 are absent logic, not broken code — the code runs fine, it just doesn't do what a real bank would do. Copilot has to infer intent to catch those, and it usually doesn't. Bug 3 (Costa Coffee shown as income) is a content error in HTML data, not a syntax issue — it also slips through.

Try it yourself before the session. You'll see it get the obvious ones and confidently miss the rest.

⚠️
Watch for Agent mode specifically — it's more powerful than Chat
Discovered during facilitator testing, worth knowing before Friday

Copilot in VS Code has two modes: Ask/Chat mode (converses, suggests, doesn't touch files) and Agent mode (reads and edits files directly, autonomously, multi-step). Nova's instructions apply in both — but Agent mode's whole purpose is to act, so a student who switches to it and says "fix this" is far more likely to get changes actually applied than one using regular Chat, even with Nova's restraint instructions present.

Nova's file has been updated with an explicit hard rule for this: in Agent mode during the Bug Hunt, it should make one small change, then stop and explain, rather than continuing autonomously. Worth testing yourself before the session — try switching to Agent mode and asking it to "fix the bugs in this file," and see whether it behaves as expected.

If a group discovers Agent mode fixes multiple bugs at once anyway: this is the same teaching moment as the "fix everything" scenario above, just a more powerful version of it. Stop the room, look at what actually got fixed together, and ask "did switching modes help you understand this any better, or just get it done faster?" That distinction — speed versus understanding — is the whole point of the exercise either way.
📋
The bug log is your real defence
Accountability built into the format

The on-screen brief asks participants to record three things for every bug they find: what was wrong, how they found it, what they changed. Copilot can fix code — it can't fill in that log. And at share-out, they have to explain each bug to the room. If they can't, it doesn't count.

Say this explicitly at the start, before anyone even opens the file:

Say this: "You could ask Copilot to fix everything in one go. But at the end you'll have to explain each bug to the room — what it was, why it mattered, how you found it. So it's up to you whether that's a useful shortcut."

That reframes it socially without sounding like a rule. Most participants self-regulate once they know there's a public explanation at the end.

⚡
If someone does it anyway: use it as the teaching moment
Don't shut it down — stop the room

If a group asks Copilot to fix everything at once, that's actually gold. Stop the room and run it live as a demonstration:

Say this: "This group just asked Copilot to fix all the bugs in one go. Let's see what it got. Did it find them all? What did it miss?"

Walk through what it caught and what it didn't — together. This is probably the single most powerful demonstration of the session's core message: Copilot speeds up the middle of the debugging loop, but you still have to run the loop. You can't outsource understanding the problem.

02
Invisible balance
CSS Easy
What goes wrong
The balance amount is in the HTML but completely invisible — dark navy text on a dark navy card background.
How to find it
The balance section appears blank. Inspect the element or search the CSS for .balance-amount and compare the colour value to the card background.
The fix
.balance-amount {
-   color: #0F1340;   /* same as the card background */
+   color: #FFFFFF;   /* white, visible on dark card  */
}
03
Wrong transaction sign
HTML Easy
What goes wrong
The Costa Coffee transaction shows as money in (+£3.80, green) instead of money out. A coffee purchase shouldn't add to your balance.
How to find it
Look at the transactions list — the coffee entry is green with a plus sign. Find the Costa Coffee entry in the HTML and check the class and amount.
The fix
- <div class="tx-amount credit">+£3.80</div>
+ <div class="tx-amount debit">−£3.80</div>
04
Wrong input type
HTML Medium
What goes wrong
The withdrawal field accepts any text, including letters. Typing "hello" corrupts the balance display with NaN. On mobile, the numeric keypad also won't appear.
How to find it
Try typing a letter into the withdrawal field — it accepts it. Look at the input element's type attribute in the HTML.
The fix
- <input type="text" id="withdraw-amount" placeholder="0.00">
+ <input type="number" id="withdraw-amount" placeholder="0.00">
05
Button typo — does nothing
HTML Medium
What goes wrong
The Withdraw button looks normal but clicking it does absolutely nothing. No error, no response — it silently fails because the event handler name is wrong.
How to find it
Click the Withdraw button — nothing happens. Find the button in the HTML and read the attribute name very carefully: onlick vs onclick.
The fix
- <button class="btn" onlick="makeWithdrawal()">Withdraw</button>
+ <button class="btn" onclick="makeWithdrawal()">Withdraw</button>
06
Wrong operator — withdrawal adds money
JS Medium
What goes wrong
Withdrawing money increases the balance. balance + amount adds the withdrawal instead of deducting it — the more you take out, the richer you get.
How to find it
After fixing bugs 4 and 5, enter an amount and click Withdraw — the balance goes up. Read the makeWithdrawal function and find the calculation.
The fix
// Deduct the withdrawal from the current balance
- balance = balance + amount;
+ balance = balance - amount;
07
Element ID typo — crashes the update
JS Hard
What goes wrong
The function tries to find an element that doesn't exist. JavaScript throws a TypeError: Cannot set properties of null in the browser console. The balance on the hero card never updates.
How to find it
Press F12 → Console and trigger a withdrawal. A red error appears. Or compare "balence-display" in the JS to the actual id "balance-display" in the HTML.
The fix
// Update the balance shown on the hero card
- document.getElementById("balence-display").textContent = ...
+ document.getElementById("balance-display").textContent = ...
08
NaN on empty input
Logic Hard
What goes wrong
Clicking Withdraw without entering an amount causes parseFloat("") to return NaN. The balance then displays as £NaN and the success message reads Withdrawn £NaN.
How to find it
Click Withdraw without entering anything. See £NaN. Then read the function — there's no if check before the calculation runs.
The fix — add this before the calculation
const amount = parseFloat(document.getElementById("withdraw-amount").value);

+ if (isNaN(amount) || amount <= 0) {
+   errorEl.style.display = "block";
+   errorEl.textContent = "Please enter a valid amount.";
+   return;
+ }

balance = balance - amount;
09
Wrong interest formula
JS Hard
What goes wrong
The rate is used directly (e.g. 5 for 5%) rather than converted to a decimal (0.05). £1,000 at 5% should earn £50/year — the buggy formula returns £600.
How to find it
Enter a principal and rate and check against a phone calculator. The answer will be 100× too high. Then read the calculateInterest function.
The fix
// Annual interest = principal × rate × 12 months
- const interest = principal * rate * 12;
+ const interest = principal * (rate / 100) * 12;
10
No overdraft check
Logic Stretch
What goes wrong
You can withdraw £5,000 from a £1,250 account. The balance goes negative. No real bank allows this without an agreed overdraft facility.
How to find it
Withdraw more than the current balance — it goes negative. Read the function: there's no check before the deduction runs.
The fix — add after the NaN check
+ if (amount > balance) {
+   errorEl.style.display = "block";
+   errorEl.textContent =
+     "Insufficient funds. Your balance is £" + balance.toFixed(2);
+   return;
+ }

balance = balance - amount;
The fully corrected makeWithdrawal()
What the function looks like once bugs 6, 7, 8, and 10 are all fixed. Useful if someone gets tangled fixing them in sequence.
makeWithdrawal() — corrected
function makeWithdrawal() {
  const successEl = document.getElementById("wd-success");
  const errorEl   = document.getElementById("wd-error");

  successEl.style.display = "none";
  errorEl.style.display   = "none";

  const amount = parseFloat(document.getElementById("withdraw-amount").value);

  // Bug 8 fix: validate input
  if (isNaN(amount) || amount <= 0) {
    errorEl.style.display = "block";
    errorEl.textContent = "Please enter a valid amount.";
    return;
  }

  // Bug 10 fix: overdraft check
  if (amount > balance) {
    errorEl.style.display = "block";
    errorEl.textContent = "Insufficient funds. Balance: £" + balance.toFixed(2);
    return;
  }

  // Bug 6 fix: subtract, not add
  balance = balance - amount;

  // Bug 7 fix: correct element ID
  document.getElementById("balance-display").textContent =
    "£" + balance.toFixed(2);

  successEl.style.display = "block";
  successEl.textContent =
    "Withdrawn £" + amount.toFixed(2) + ". New balance: £" + balance.toFixed(2);
}
