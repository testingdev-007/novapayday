Troubleshooting Card
One page. If this happens, do this. Nothing to search for.
💻Technical — Codespaces & Copilot
Codespace won't load / stuck loading
Wait up to 3 minutes on first load — that's normal. Still stuck? Close the tab, go back to their repo, Code → Codespaces → try again. Nuclear option: they use a GitHub Gist or CodePen with the same file as backup.
"Open with Live Server" isn't showing
Extensions still installing. Wait 30 seconds, right-click the file again.
Copilot icon missing or greyed out
They're not signed in. Click the account icon bottom-left of VS Code → sign in with GitHub.
Copilot Chat gives generic answers, not "Nova"
The .github/copilot-instructions.md file is missing or misnamed in their repo. If it happened to everyone, it's your template — fix and tell them to make a fresh copy. If it's one group only, they may have started before you added Nova.
Level Up challenges "don't work" / no ghost text appears
Inline completions only work inside a Codespace, never on the github.com website itself. Confirm they're in their actual Codespace and that challenge.js shows up in their file panel — it's pre-loaded in the repo, so if it's missing they may need to pull the latest changes or their Codespace predates the file being added.
A commit/push from Codespaces just hangs, does nothing
Use the terminal instead of the Source Control panel — git add ., git commit -m "x", git push — the terminal shows the real error where the UI just spins. Still nothing? Reload the browser tab to reconnect, then retry.
A file was created on github.com directly, not in the Codespace
The Codespace won't see it automatically. Run git pull in the Codespace terminal to bring it down. If it complains about conflicts, the Codespace has local changes fighting the website version — sort out which version to keep before retrying.
A group wants to undo a bad commit
Simplest safe method: on GitHub, open the file → History → click the commit before things broke → copy that version's content → paste it back into the current file → commit again. No advanced git needed.
Copilot refuses a request, mentions "SQL injection" or similar out of nowhere
Usually means the code was asked about directly in the chat box rather than saved in a real file first. Get them to actually paste and save the code in challenge.js (or the relevant file), then ask Chat about that file — the false-positive tends to clear up once there's a real file behind it.
A page shows a red error / doesn't work at all
Press F12 → Console tab. Read the red text (or get them to). Paste it into Nova and ask what it means.
Someone breaks their Codespace badly
Delete it (github.com/codespaces → delete) and create a fresh one from their own repo. Their saved file usually survives — if not, rebuilding from their paper plan is much faster the second time. Reassure them of that.
Whole internet / Codespaces outage (rare, nuclear)
Your laptop + projector becomes the shared computer. Groups take turns directing you — you type only what they say. Genuinely still works, and it's fun.
🧑‍🤝‍🧑The room — groups and pacing
"It's not working" (vague)
"What did you expect it to do, and what's it doing instead?" Then: "Ask Nova exactly that."
"Can you just fix it for me?"
"I can't — but Nova can walk you through it, and I'll sit with you while it does." Then actually sit with them for a minute.
A group can't think of a feature idea
Point at the back-pocket gallery on the brainstorm screen. Savings Goal Tracker is the safe default.
A group finishes everything early
"Can you break it? Try entering -100. Leave a box blank." Then point them at stretch goals on the milestone screen.
A group is badly behind at the checkpoint
"Strip it back — one input, one button, one number on screen. Get that working, then add back." Say it to the room, not just to them, so it doesn't feel singled out.
Whole room is behind, not just one group
Cut a milestone entirely and announce it: "New plan — everyone's goal is a working version 2. Stretch goals are for next time." Confidence, not apology.
One group is way ahead, getting bored
"You're now junior mentors — adopt another group for 15 minutes." Explaining is the best way to deepen their own understanding.
Two people fighting over the keyboard
Driver/navigator rule — one types, one directs, swap every 10 minutes.
A live demo breaks in front of everyone
"Congratulations — a live demo failure. That's the most authentic developer experience of the day." Let them show it in the editor instead.
Nova/Copilot gives wrong code and a student trusts it
Best teaching moment available: "It's confident and wrong — same as the interest bug this morning. What test would prove it right or wrong?"
Nova's hint-based restraint is genuinely too much for one student
Each student has their own repo, so this only ever affects one person, not the room. On github.com, rename or delete their .github/copilot-instructions.md → have them rebuild the Codespace (command palette → "Rebuild Container") → Copilot reverts to plain, unrestricted behaviour for that student only. Re-add the file the same way afterward if you want it back.
🫶You
You genuinely don't know the answer
Open your own Copilot Chat, paste the problem in, work through Nova's answer with the student, out loud. "Let's find out together" is better teaching than knowing.
You feel like you're falling behind on time
Cut scope, not quality. A tiny feature that works beats an ambitious one that doesn't. Nobody remembers what you cut if you sound confident cutting it.
