NovaPay Workshop — Admin
Facilitator Setup Guide
Start here if you have no GitHub account, no organisation, and no seats. This takes you from zero to a fully working workshop environment. Allow about 30–40 minutes.
👤
Part 1 — Your GitHub Account
Skip this part if you already have one
1
Create a free GitHub account

Go to github.com → click Sign up. Enter your email, create a password, choose a username. Verify your email when the confirmation arrives.

Free account is fine
You don't need a paid personal GitHub account. The Copilot seats come from the organisation plan you set up in Part 2.
🏢
Part 2 — Create Your Organisation
An org is where you manage members and Copilot seats centrally
2
Create a new organisation

When logged in to GitHub, click the + icon in the top right → New organisation.

Choose the Free plan — you don't need a paid org plan. Copilot is added separately on top. Give the org a name (e.g. novapay-workshop or your programme name). Set it as belonging to your personal account.

Choose your org name carefully
The org name appears in all your URLs and can't easily be changed later. Keep it short and relevant to your programme.
💺
Part 3 — Enable Copilot Seats
Purchase and configure seats for your participants
3
Open Copilot settings in your org

Go to your organisation page → Settings tab (along the top) → scroll down the left sidebar to Copilot.

Click Enable GitHub Copilot or Start free trial if available. Select GitHub Copilot Business and choose the number of seats you need — one per participant plus one for yourself to test with.

Seat assignment is flexible
Seats are assigned per-person and can be reassigned. You only pay for seats you've allocated, so you can add them one at a time as participants confirm.
⚙️
Part 4 — Set the Repo Policy
Critical — without this, Copilot won't work in participants' personal repos
4
Allow Copilot in all repositories

Still in your org's Settings → Copilot, find the Policies section.

Look for a setting about where Copilot can be used — it will say something like "Allow GitHub Copilot to be used in" with options. Make sure this is set to All repositories, not just org-owned ones.

This step is easy to miss
Participants will be working in their own personal repos (copies of your template). If this is set to org repos only, Copilot will silently not work for them. Check this before the session.
📁
Part 5 — Create the Template Repo
The repo participants will copy to get their own workspace
5
Create a new public repository

Click + → New repository. Set the owner to your personal account (not the org). Name it novapay-workshop. Set it to Public. Tick Add a README file. Click Create repository.

Why personal, not org?
Template repos work best from personal accounts for this setup. Participants use "Use this template" to copy it to their own account — keeping it personal and clean.
6
Upload all three workshop files

On your new repo page, click Add file → Upload files. Drag in all three at the same time:

  • bank-dashboard.html — the buggy NovaPay dashboard for Hour 1
  • starter-template.html — optional reference for the Feature Tutorial
  • challenge.js — pre-loaded with a buggy function for Level Up Round 1

Scroll down and click Commit changes.

Why three files?
bank-dashboard.html is the Hour 1 bug hunt exercise. starter-template.html holds a partially-built version of the Feature Tutorial's Savings Tracker — an optional reference if a group wants to compare their work against a finished version. challenge.js is used during Level Up — it already contains a buggy function so Round 1 can start by asking Copilot to fix a real file, rather than pasting code cold into chat.
7
Add the Codespaces config file

Click Add file → Create new file. In the filename box type exactly:

.devcontainer/devcontainer.json

Typing the / automatically creates the folder. Then paste this into the file content area:

{
  "name": "NovaPay Workshop",
  "customizations": {
    "vscode": {
      "extensions": [
        "ritwickdey.LiveServer",
        "GitHub.copilot",
        "GitHub.copilot-chat"
      ],
      "settings": {
        "liveServer.settings.port": 5500,
        "liveServer.settings.donotShowInfoMsg": true
      }
    }
  },
  "forwardPorts": [5500]
}

Click Commit new file.

What this does
This file tells Codespaces to automatically install Live Server and Copilot extensions every time someone opens a new workspace. Without it, participants would have to install extensions manually.
8
Make it a template repository

Go to your repo's Settings tab → scroll to the General section → tick Template repository. It saves automatically.

Your repo page will now show a Use this template button. That's what participants click.

👥
Part 6 — Add Participants
Invite to org and assign Copilot seats
9
Collect GitHub usernames in advance

Before the session, ask participants to create a GitHub account and send you their username. Even a quick message the day before helps enormously — it means seats are assigned before they walk in.

Age note
GitHub's minimum age is 13. For any 12-year-old participants, create a GitHub account in advance yourself (use a programme email address) and hand them the login on the day. Pre-assign a seat to that account.
10
Invite participants to your org

Go to your org page → People tab → Invite member. Enter each participant's GitHub username or email address. Set their role to Member.

They'll receive an email invitation to join. They need to accept it before you can assign them a Copilot seat.

11
Assign Copilot seats

Org Settings → Copilot → Seat management. Click Add users. Select each participant's account and confirm.

Once assigned, Copilot is active on their account — they can use it in any repo they work in (because you set the policy to all repositories in step 4).

Seat assignment takes effect immediately
No waiting, no restart needed. As soon as you assign the seat, Copilot works for that user.
💡
Understanding Codespaces — if you only know GitHub Pages
Read this before your test run — it will make everything make sense
?
What's the difference between GitHub Pages and Codespaces?

You already know GitHub Pages: you upload an HTML file, GitHub serves it as a public website, anyone can visit the URL. The file lives in the repo and GitHub does the hosting.

Codespaces is completely different. Instead of serving your file as a website, GitHub spins up a full cloud computer — a virtual Linux machine — and gives each person access to it through their browser. Inside that cloud computer, VS Code opens automatically, your files are there, and you edit them directly.

There's no public URL. Nothing is published. It's more like giving everyone their own laptop to work on, except the laptop lives in Microsoft's data centre and they access it through a browser tab.

The key difference in one sentence
GitHub Pages = GitHub hosts your finished file as a website. Codespaces = GitHub gives everyone a cloud computer to write code on.
?
What will participants actually see?

When a participant opens their Codespace, a new browser tab opens showing VS Code — the same code editor that professional developers use — running entirely in the browser. They don't install anything.

On the left they'll see a file panel with bank-dashboard.html and starter-template.html. They click a file to open it. They edit it. They right-click it and choose Open with Live Server — this opens a second tab showing the page rendered in a browser, updating live as they type.

On the left sidebar there's also a Copilot icon. Click it, a chat panel opens on the right, they type questions in plain English.

This is why a test run is essential
You need to have seen this yourself before the session. Once you've done it once, you can describe it to participants and help anyone who gets stuck. It takes about 5 minutes to see the full experience.
?
What do you need to know on the day?

You don't need to be a VS Code expert. You need to know four things:

  • How to open a Codespace — Code button → Codespaces tab → Create codespace on main
  • How to open the preview — right-click the file → Open with Live Server
  • How to open Copilot Chat — click the Copilot icon in the left sidebar
  • How to open the browser console — press F12, click Console tab (for bug errors)

That's the full toolkit. Everything else in the session flows from those four actions.

?
Does any of my GitHub Pages knowledge transfer?

Yes — more than you might think. You already understand repos, uploading files, and that HTML is just a text file. That mental model is exactly right. The HTML files in the repo are the same files participants will edit in Codespaces — they're just editing them inside the cloud computer rather than downloading them and editing locally.

One thing that won't transfer: there's no "publish" step in this workshop. Nothing goes live as a public website. Participants work, preview in Live Server, demo from their Codespace, and that's it. That's fine — it's a workshop, not a deployment.

Part 6b — Install Nova (your virtual mentor)
One file, one paste, five minutes. Zero coding knowledge needed.
?
What you're about to do, in one sentence

You're going to create one text file in your repo, called exactly .github/copilot-instructions.md, and paste some instructions into it. That's it. GitHub Copilot automatically reads this file and changes its personality for everyone using your repo — into "Nova."

Nothing to install on your computer
You do this entirely on the github.com website, in your browser. No downloads, no terminal, no code.
A
Go to your template repo

Go to github.com/YOUR-USERNAME/novapay-workshop — the same repo where you uploaded bank-dashboard.html and starter-template.html.

B
Click "Add file"

Near the top right of the file list, click the Add file button (it's a dropdown) → click Create new file.

C
Type the exact filename

A box appears for the filename. Type exactly this, including the dot at the start and the slash in the middle:

.github/copilot-instructions.md
This part matters
The / is what tells GitHub to create a folder called .github and put the file inside it. If you get this filename wrong — even a small typo — Copilot won't read the file and Nova won't activate. Copy it exactly as shown above.
D
Paste in the Nova instructions

Below the filename box there's a big empty text area — that's where the file content goes. Open copilot-instructions.md from your materials pack, select everything in it (Ctrl+A or Cmd+A), copy it, and paste the whole thing into that box.

E
Commit the file

Scroll to the bottom of the page. Click the green Commit changes... button, then confirm on the dialog that pops up (default options are fine). Done — Nova is now live in your repo.

✓
How to check it worked

Create a fresh test Codespace from your template (same as your usual test process). Open Copilot Chat and type: Who are you?

If Nova is working, it should describe itself as a NovaPay mentor rather than giving a generic "I'm GitHub Copilot" answer. If it gives the generic answer, double-check the filename in step C — that's the only step that commonly goes wrong.

!
Important — this must happen BEFORE participants create their Codespaces

Nova is copied into each participant's own repo the moment they click "Use this template." If you add the Nova file to your template after some participants have already made their copies, those participants won't have it.

The fix if this happens on the day
Ask them to delete their personal repo (Settings → scroll to bottom → Delete this repository) and click "Use this template" again from your master repo. Their own code isn't safely recoverable this way, so this is best avoided by doing this step properly, before the session, once.

Part 7 — Test End-to-End
Do this yourself before the session — ideally the day before
12
Run the full participant flow yourself
Go to your repo URL and click Use this template
Create a test repo (call it test-novapay), set to Public
Click Code → Codespaces → Create codespace on main
Wait for the Codespace to load (1–2 minutes first time)
Right-click bank-dashboard.html → Open with Live Server
Confirm the NovaPay dashboard appears in a browser preview tab
Click the Copilot icon in the left sidebar — confirm Chat opens
Type a test message in Chat — confirm it responds
Delete the test repo when done (Settings → scroll to bottom → Delete)
If everything above works, you're ready
Write down your template repo URL: github.com/YOUR-USERNAME/novapay-workshop — that's the only URL you need to share on the day.
